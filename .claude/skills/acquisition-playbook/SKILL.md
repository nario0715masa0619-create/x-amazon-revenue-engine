# acquisition-playbook (集客モード)

## 目的

まだ自分のアカウントを知らない・フォローしていない層に対して、新規接触を生み、プロフィールへの遷移・フォローにつなげる。このモードでは「売る」ことを目的にしない。

## 使う場面

- 現在モードが `acquisition`(`ops/state/current_mode.yaml`)のとき
- フォロワー数・インプレッションが伸び悩んでいるとき
- 新しいテーマ・切り口でリーチを広げたいとき

## 入力

- x-researcher による市場・話題性の調査結果(あれば)
- 直近の集客モード投稿の成果(performance-analystの分析、あれば)

## 出力

- 集客向け投稿案(目的: 新規接触・プロフィール遷移・興味喚起)
- 狙うKPI: `impressions`, `profile_visit_rate`, `follow_rate`

## 設計方針

- フックは「共感」「意外性」「有用な単発情報」を優先する。商品リンクや強いCTAは基本的に置かない
- 保存・引用したくなる情報密度を意識する(ただしeducationモードほどの網羅性は不要)
- プロフィールに何があるか気になる終わり方(続きはプロフィールへ、等)を検討する
- 同一トピックの連投を避け、話題の幅を広げる

## チェックポイント

- [ ] 商品の直接的な購入訴求になっていないか(→ salesモードの内容が混ざっていないか)
- [ ] フックの冒頭1〜2文で読者が止まる作りになっているか
- [ ] プロフィール遷移導線が明確か
- [ ] 同種のフックを直近投稿で使っていないか(`ops/logs/post_log.jsonl` を確認)

## 失敗例

- 集客モードのはずが商品リンクを本文に入れてしまい、実質salesモードの投稿になっている
- フックが弱く、本文を読まないと何の投稿か分からない
- 毎回同じ構文(「〜な人に知ってほしい」等)を使い回し、フォロワーに飽きられる
- KPIを意識せず「なんとなく良さそうな投稿」を作ってしまい、効果検証ができない
