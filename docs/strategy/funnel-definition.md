# funnel-definition.md — 集客/教育/販売の定義

## モードとは何か

モードは「今この投稿・施策が、ファネルのどの段階を担っているか」を示す分類である。担当（roles）とは独立した軸であり、`ops/state/current_mode.yaml` で現在の重点モードを管理する。

3モードは互いに排他的な「投稿のジャンル」ではなく、**読者が意思決定に至るまでの心理的な距離**を表す。

## 各モードの定義

### 集客（acquisition）

- **目的**: まだ接点のない層に発見してもらい、フォロー・プロフィール遷移につなげる
- **読者の状態**: 商品カテゴリへの関心はあるかもしれないが、このアカウントを知らない
- **やること**: 興味喚起、共感、単発で価値のある情報提供
- **やらないこと**: 具体的な商品の強い購入訴求
- **主なKPI**: `impressions`, `profile_visit_rate`, `follow_rate`

### 教育（education）

- **目的**: 商品カテゴリの理解を深め、比較軸・選び方・失敗回避の知識を提供し、信頼を積み上げる
- **読者の状態**: アカウントをフォローしている、または興味を持って読んでいるが、まだ購入の意思決定に至っていない
- **やること**: 比較、選び方の解説、よくある失敗の共有、保存したくなる情報整理
- **やらないこと**: 特定商品への断定的な優劣付け、強いCTA
- **主なKPI**: `save_rate`, `reply_rate`, `link_preclick_interest`

### 販売（sales）

- **目的**: 具体的な商品提案と明確なCTAで、Amazon商品ページへの遷移と購入を後押しする
- **読者の状態**: 商品カテゴリへの理解があり、意思決定の後押しを必要としている
- **やること**: 意思決定支援、明確なCTA、開示を伴った商品紹介
- **やらないこと**: コンプラレビュー未通過での投稿確定
- **主なKPI**: `ctr`, `conversion`, `revenue`, `epc`

## モード切替の考え方

- モードは日替わりで機械的に切り替えるものではなく、**直近のログとファネル全体のバランス**を見て `mode-orchestrator` が判断する
- 初期値は `ops/state/mode_weights.yaml` の比率（集客0.5 / 教育0.3 / 販売0.2）に従う。これは「集客がファネルの入口であり最も投稿頻度を要する」という前提に基づく初期値であり、固定ではない
- 比率の見直しは、思いつきではなく `weekly-pdca-review` skill の分析結果に基づいて行う
- 1つの投稿は基本的に1つのモードに属する。複数モードの要素を1投稿に混在させない（例: 集客投稿に強いCTAを混ぜない）。これは表現の一貫性とコンプラレビューのしやすさのため

## モードとKPIの関係

モードを跨いだKPI比較（例: 集客の`follow_rate`と販売の`conversion`を同列に比較する）は意味を持たない。モードごとに「何を改善できたら成功か」を分けて評価する。詳細は [kpi-definition.md](kpi-definition.md) を参照。
