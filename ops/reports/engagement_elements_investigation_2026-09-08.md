# engagement_elements_investigation_2026-09-08.md — エンゲージメント要素付与機構の調査・実装記録

## 背景

別チームの投稿（40代男性のバッグの中身、ハッシュタグ2つ・末尾にエンゲージメント質問あり）が
48時間で137インプレッションを記録し、既存4本（各50〜170インプレッション、100時間以上経過、
エンゲージメント全て0）を伸び率で上回った。この差の要因調査（2026-09-08、read-only調査タスク）を
受けて、`GenerationSlots`にハッシュタグ・エンゲージメント質問文の付与機構を新設した。

## フェーズ0: Gate Aへの影響確認（実測）

既存4件（デニム-定番-服__定番、コーデ-デニム-服__テク、メンズ-大人-服__おすすめ、垢抜け-服）の
実際に記録済みのdraft本文へ、ダミーのハッシュタグ・質問文を追加して`run_gate_a()`（既存・無変更）を
実行し、Gate Aの実際の判定を確認した。

### 検証1: baseline（追加なし）vs ハッシュタグ+質問文追加

| 候補 | baseline | ハッシュタグ+質問文追加 |
|---|---|---|
| デニム-定番-服__定番 | pass | **reject**（禁止文体: CTA混入「みんなは普段どうしてる？」） |
| コーデ-デニム-服__テク | pass | **reject**（禁止文体: CTA混入「みんなは普段どうしてる？」） |
| メンズ-大人-服__おすすめ | pass | **reject**（禁止文体: 日記/独白化、source欠損への対応不備） |
| 垢抜け-服 | pass | **reject**（禁止文体: CTA混入、source欠損への対応不備） |

4件中4件のbaselineがpassし、4件中4件の追加版がrejectされた。

### 検証2: 質問文のみ vs ハッシュタグのみ（切り分け）

デニム-定番-服__定番のdraftを使い、質問文のみ／ハッシュタグのみに分けて再検証した:

- **質問文のみ**: reject。理由「禁止文体: CTA混入（『みんなは普段どうしてる？』という問いが含まれている）」— **これはGate Aの既存・意図的なルールであり、非決定性のノイズではない**。3回のテスト（検証1の3件＋この単独テスト）すべてで一貫して同じ理由（CTA混入）が返された。
- **ハッシュタグのみ**: reject。理由「構造崩壊: comparison構造の元投稿が単なる感想文になっている」「禁止文体: 記事紹介化」— ハッシュタグそのものへの言及は無く、内容とも整合しない理由。

### 検証3: ハッシュタグのみを4件全件で再検証

4件全てにハッシュタグのみ（質問文なし）を追加し再検証した:

| 候補 | 結果 | reject理由 |
|---|---|---|
| デニム-定番-服__定番 | reject | 構造崩壊、禁止文体: 日記/独白化 |
| コーデ-デニム-服__テク | reject | source_full_textの範囲を超えた一般化・断定 |
| メンズ-大人-服__おすすめ | reject | 原文に無い体験の詳細の追加、禁止文体: 日記/独白化、一般化・断定 |
| 垢抜け-服 | reject | source_full_textに無いage_angle（40代）の追加 |

**4件とも却下されたが、理由はいずれもハッシュタグと無関係かつ相互に一貫性が無い。** これは
本リポジトリのPDCA履歴で既に複数回記録されている「Gate A/Bの監査結果の非決定性」
（`ops/reports/pdca_experiment_registry.md`参照）と整合する挙動であり、「ハッシュタグを
意図的に禁止するルール」がGate Aに存在するとは判断できない。

### 結論

| 要素 | Gate Aの反応 | 性質 |
|---|---|---|
| `engagement_question`（末尾の質問文） | **一貫してreject**（CTA混入） | Gate Aの意図的な既存ルール |
| `hashtags`（末尾のハッシュタグ） | rejectするが理由が無関係・非一貫 | 既知の監査非決定性による可能性が高い |

**設計判断（重要）**: Gate Aの「CTA混入」ルールは、`docs/policies/x-posting-policy.md`の
「通報・批判が集まりやすい表現を避ける」「アカウントの長期的な信頼が短期的なクリック数より
優先される」という既存方針と整合する、意図的な安全機構であると判断した。依頼文では
「監査対象の本文からハッシュタグ・質問文を除外して回避できるか検討する」ことが求められていたが、
**この回避（Gate A監査を経由しない形での本文結合）は実装しなかった。** 理由:

1. `engagement_question`のreject理由は3回とも「CTA混入」という一貫した意図的ルールであり、
   単純な非決定性のノイズではない。これを監査対象から除外することは、Gate Aが実際に
   機能している安全機構を意図的に迂回することを意味する。
2. Gate A/thresholds/shipping decisionは本タスク・本セッション全体を通じて「触ってはいけない
   領域」として明示されてきた。ロジック自体を変更しないことと、そのロジックが実際に
   評価する対象を意図的に狭めて実質的に無力化することは、目的の観点では同じ結果になり得る。
3. CLAUDE.mdの「迷ったときの優先順位」は「1. 安全（コンプラ・開示・アカウント健全性）」を
   最優先に置いている。エンゲージメント率の改善（3の「施策の効果」）を理由に1を犠牲にしない。

そのため、`GenerationSlots.hashtags`/`engagement_question`は**デフォルトNone・完全に
opt-in**の実装に留め、既存の`render_draft()`の呼び出し経路（Gate A/B監査を含む）を
一切変更していない。これらのスロットを設定した場合、生成されたdraft本文はハッシュタグ・
質問文を含んだ状態でそのままGate A/Bの監査対象になる（監査からの除外・迂回は行っていない）。
`engagement_question`を実運用で有効化する場合、高い確率でGate Aに却下される見込みが高いことを
理解した上で人間が判断すること。

## 実装内容

- `scripts/draft_generation_templates.py`:
  - `GenerationSlots`に`hashtags: list[str] | None = None`・`engagement_question: str | None = None`を追加
  - `_append_engagement_elements()`（新設）: テンプレート本体の末尾に、指定があれば追記する共通関数
  - 全8テンプレート関数（`render_listicle`/`render_comparison`/`render_priority_reversal`/
    `render_experience_review`/`render_how_to`/`render_headline_assertion_fashion`/
    `render_single_claim`/`render_essay_reflection`）の返り値を`_append_engagement_elements()`
    経由に変更（骨格の組み立てロジック自体は無変更、末尾への追加のみ）
- `scripts/test_engagement_elements.py`（新設）: 後方互換性（未指定時は出力が完全一致）・
  8テンプレート全てでの付与動作を検証（15件全PASS）
